# HOSTED4: Hosted Security Gate

Status: executable vertical slice  
Tracking: #48

HOSTED4 closes the control plane before the public CLI starts consuming it.

## Control-plane authentication

Provisioning requires a bearer control token:

```http
POST /_hooktry/hosted/exposures
Authorization: Bearer <HOOKTRY_CONTROL_TOKEN>
```

The health endpoints stay public:

```text
GET /healthz
GET /_hooktry/health
```

The hosted process refuses to start unless `HOOKTRY_CONTROL_TOKEN` is present and non-empty.

The startup JSON never prints the control token.

## Runtime capabilities

Runtime registration uses a separate capability issued per Exposure.

HOSTED4 changes capabilities from UUID-derived tokens to 256 bits generated by a cryptographically secure RNG. The presented token has the form:

```text
hooktry_rt_<64 lowercase hex characters>
```

Only the SHA-256 digest is stored in `CapabilityStore`; the raw secret is returned once to the provisioning caller and then used by the runtime in the WebSocket `Authorization` header.

Capabilities remain:

- scoped to one Exposure
- expiring
- revocable
- absent from public and runtime URLs

## Separation of authority

```text
control token
    -> may provision Exposure + receive runtime capability

runtime capability
    -> may register exactly one runtime for one Exposure

public URL
    -> routes inbound traffic only
```

These are deliberately separate authorities.
